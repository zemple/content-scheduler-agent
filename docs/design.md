# 素材审核与发布排期 Agent 设计

题号 1；依据用户提供的完整题面及已讨论方案。用户已要求直接完成交付。

采用 Python 标准库、原生单动作模型循环、SQLite、CLI。比较过 LangGraph（状态图清晰但本题增加依赖）及纯固定流程（离线可运行但不满足真实 ReAct）；选择原生实现，模型决定工具及参数，业务工具强制约束。无界面、部署、真实发布、多 Agent 业务流程。

请求包含 request_id、items（material_id、requested_time、hard_time）及可选 confirmations。时间必须带时区，统一 UTC 比较；合成业务约束：同频道每小时最多一个已确认草稿/已有排期，时间必须整点。用户确认由 CLI 输入读取，不对模型开放确认工具。

四个业务工具：read_material、check_rules、query_slots、save_draft；finish 为结束控制工具。每次最多一个动作，工具结果反馈模型，12 步默认上限，模型错误显式 incomplete。缺字段不通过，版权失败/禁用声明阻断，人工审核标签待确认且不可保存为已确认。硬性时间变更未获明确确认只能作为待确认草稿。待确认草稿不占时段；已确认草稿事务内再次检查冲突并占位。无 publish 工具。

工具重新读取真实材料和规则，不接受模型伪造审核结果；SQLite 唯一键 (request_id, material_id)，请求 ID 对应规范化内容摘要，内容不同拒绝。同一请求不覆盖旧草稿；确认变更用新的 request_id。模型建议为非权威数据，最终状态来自工具观测与数据库。

每步记录公开动作依据（不是内部思维）、参数、完整工具观测、摘要和后续动作。Mock 是固定策略，仅验证流程；真实 API 运行另存 live 目录，不得把 Mock 当真实模型效果。所有资料合成。保存/读工具失败可注入，错误不得写成成功。

覆盖六项必验，以及时段变化、确认、多个素材、上限、模型故障、并发、恶意动作。交付五份指定文档、README、依赖、环境示例、可执行测试、输入/输出/Trace、Git 提交。真实运行和 GitHub URL 以可用接口和账号授权验证为准，缺失即明确列为未完成。
