# 扩展数据与排期约束

用户已批准上一条建议：约20条素材、一周三个频道、只允许提前/时间窗口/截止时间、固定与灵活素材竞争、保留新数据验证。继续使用原生模型循环和整点时段，不扩展为视频内容审核或任意区间重叠算法。

## 设计

- 原有字段及用例保持兼容。items 新增可选 `not_before`、`not_after`（含边界）、`deadline`（不含边界）、`adjustment`（either/earlier_only/later_only）。硬性时间改变仍需用户确认；其他约束不能靠时间确认绕过。严格校验矛盾的约束和不合法字段。
- 新增 constraints.py，在查询、保存、最终旧草稿重验中共用约束判断。查询区分 occupied 与 constraint_violations，available 仅当无占用且满足约束。
- 模型负责选择查询起点、观察变化并选择可行时段。工具仍检查约束，不自动替模型保存其他时段。固定素材的目标时段在同批内优先保护，避免灵活素材先占用；这是声明的启发式保护，不声称全局最优。
- 离线策略独立按约束查询有限窗口，默认查询每次最多6个小时，执行上限仍保留。时间粒度仍为UTC整点，同频道互斥。
- 默认数据扩到20条素材、2026-11-01到11-07、video/social/community三个频道；保留旧例18->19->20的起始环境。额外data/evaluation套件含开发场景与验证场景，验证集不放正确答案进模型输入。
- 保留旧examples基线作为历史执行证据；新examples/expanded分别生成mock/live，以及开发与验证汇总。旧资料和输入快照不改写。
