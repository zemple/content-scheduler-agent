# 04 · AI 使用与贡献边界

## 如实说明

本项目在允许 AI 辅助的考核规则下，由候选人与 Codex 协作完成。AI 辅助范围包括方案细化、代码与测试编写、合成资料、文档初稿、运行与调试、真实模型调用验证以及交付整理。不能把 AI 生成代码描述成候选人完全独立手写。

候选人在本次对话中实际完成：提供完整题面和交付要求；选择题号 1；确认开始实现；提供模型访问配置及 GitHub 账号；决定公开仓库供评审查看。尚无证据表明候选人已经独立修改某段代码或逐行验证全部逻辑，因此这里不编造个人修改记录。

候选人在正式提交前应实际运行、理解并按自身判断修改项目；若有后续修改，在此补充具体文件、原因和验证结果。当前不把这项尚未发生的个人学习活动写成已完成。

## 两类不同 AI 使用

1. 开发辅助：Codex 生成和修改工程材料，执行测试；另有独立审查代理只读检查核心代码，发现畸形工具名和日期溢出边界。审查代理不是业务运行链路的一部分。
2. 项目运行：ChatModel 调用真实 API，模型自主选择业务工具及参数；实际版本和响应 ID 记录在 examples/live。MockModel 是普通确定性程序，不是真实模型。

## AI 输出如何被验证

- 自动测试验证确认边界、规则阻断、SQLite 幂等/并发、状态与退出码；不是只检查提示词里写了哪些规则。
- 本机 HTTP 测试服务器验证原生 function calling 的请求和结果回传关系；测试不调用付费模型。
- 真实模型逐场景运行，使用实际工具输出和数据库行数检查预期；保留至少一次过早结束的失败记录，而非只挑成功截图。
- 更换占用时段、改变规则并重复请求，确认动作/状态会变化。
- 密钥仅在本机忽略配置中，API 错误只记录状态码，不记录请求头或密钥。

## 不能从结果推出的结论

单次场景通过不代表生产效果或统计成功率；合成元数据审核不能代替真实素材内容审核；Mock 通过不证明真实模型具备决策能力；自动运行时间不等于候选人独立工作时间。最终交付以保存的文件和实际 Git commit 为依据。
