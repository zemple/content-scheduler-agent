# 01 · 需求

## 用户、目标与范围

用户是内容团队运营人员。目标是从指定素材中识别资料缺口和规则风险，检查已有排期，生成无冲突、可确认的排期草稿。题号 1，CLI 作为唯一必需运行入口。不执行真实发布、不做生产级 Runtime、不要求界面、多 Agent 或部署。

材料为合成数据：M01 正常、M02 缺版权确认、M03 命中演示禁用声明（没有执行事实核验）、M04 带人工审核标签、M05 第二份正常素材。默认已有排期占用 2026-11-01 北京时间 18:00。规则是演示业务规则，不声称等于真实平台审核政策。

## 输入和交付字段

- request_id：稳定请求标识，相同标识内容不可改变。
- items：1..10 项，每项有 material_id、带时区 requested_time、布尔 hard_time。
- 可选排期约束：adjustment（只能提前/推迟/任意）、not_before/not_after包含边界的窗口、deadline严格截止；查询、保存与重验一致执行。同批灵活素材不能抢占可行的固定目标时段。
- confirmations：可选；由用户输入的 material_id -> 明确确认的替代时间。
- 素材元数据、规则、已有排期：通过 data 目录 JSON 提供。
- 输出：每项审核状态、风险原因、资料缺口、建议时间、待确认项、草稿保存状态/ID、确认状态、未完成原因、工具错误和始终为 not_published 的发布状态。

## 成功标准与验收映射

| 要求 | 可检查的标准 | 验收场景/测试 |
|---|---|---|
| 正常排期 | 审核通过、空闲时段、数据库确有一份草稿 | normal / test_normal_save_persists_confirmed_draft |
| 信息缺失 | 输出缺失字段、不通过审核、不保存 | missing / test_missing_info_cannot_save |
| 规则风险 | 阻断风险禁止保存；人工审核只存 pending | risk、manual_review |
| 时段冲突 | 根据结果补查、建议空闲时段、硬性变更 pending | conflict、changed_occupancy |
| 重复提交 | 同请求重复只一份草稿、同 ID 不同内容拒绝 | duplicate、test_same_id_different_request_rejected |
| 保存失败 | 返回失败；不得虚构 ID 或成功行 | save_failure |
| 动态决策 | 真实模型观察工具结果后选择不同下一步 | normal 与 conflict 的真实 Trace |
| 执行上限 | 明确 incomplete/step_limit，保留已成功结果 | step_limit |
| 约束变化重跑 | 旧草稿保留，但不能报告当前有效 | repeat_changed_occupancy、repeat_changed_rules |
| 多项无冲突 | 同批建议不冲突，失败不抹掉已成功项 | batch_pending、batch |

每场景具体输入、实际输出、Trace、数据快照、执行状态和数据库导出都保存在 examples；文档 03 链接各文件。至少覆盖正常、资料不足、工具失败三类；本项目覆盖更多独立场景。

## 必须保持的不变量

1. 不存在发布工具；保存成功不等于发布。
2. 用户硬性要求不会被覆盖；模型不能自行生成有效用户同意。
3. 审核和保存结果由真实工具/数据库决定，不由模型文本声明。
4. 保存必须重新校验规则和占位，SQLite 事务避免并发抢占。
5. 多份待确认草稿可跨请求共享候选时段，但同批不能共享；确认时必须重验。
6. Mock 验证流程；真实模型效果只能引用 live 运行记录。

## 数据与扩展验收

默认数据为20条素材、一周64条排期、三个频道。原16项验收保留，另设8个开发场景和3个保留验证场景，具体规则与入口见advanced-scheduling.md。验证不仅核对状态，还逐份检查保存时间是否符合窗口、方向、严格截止、用户确认和同批冲突。没有声称新增自动自然语言解析或实际视频内容审核。
