# 扩展后的回归问题

本目录保存一次扩展开发中的真实模型回归：summary.json是整轮16场景统计，保留batch_pending和no_slots两个完整样本，并非完整整轮产物。

batch_pending：模型只检查两份素材的原时段，发现均占用就结束，没有补查待确认建议。这是需要改进的模型行为；增加提示明确hard_time约束确认权限，不禁止提出替代草稿。

no_slots：旧测试只占用从原时段开始的24小时，却没限制用户可以提前。模型找到更早空位并存为pending，在原始输入下并未越权；旧测试把它判为失败是用例定义不完整。修正测试请求，显式给出这24小时的允许窗口，所有允许时段才确实都被占用。

本轮conflict/changed_occupancy也出现预期19:00/20:00、实际选更早时段的差异。为使方向相关比较可解释，修正后的请求明确later_only。没有把原先允许更早时段的输入改写成“模型违反限制”；失败历史保持原样。

开发组调整后重新执行；保留验证组在最终源代码/提示冻结后才执行，未用其结果调整实现。最终记录在examples/live和examples/expanded。

后续batch完整样本也保存在batch/：加提示后仍偶发过早结束，因此最终新增运行时finish校验，把遗漏反馈给模型重新选择动作。此修正依据基线失败，非保留验证组结果；验证组最终执行按回归复测披露。
